### **Title**

Training loop only performs one forward pass per batch, inconsistent with deep supervision described in the paper

---

### **Content (English)**

**Problem description**
In the current training implementation, each training batch only executes a single forward pass of the model. Specifically, in `train_batch()`, the code calls `train_state.model(...)` once, obtains the loss, and immediately backpropagates.

However, according to the paper’s pseudocode, training should involve *deep supervision*, meaning:

* The same input should be processed for multiple **segments**.
* A loss should be computed at each segment.
* The hidden state (`carry`) should be **detached** between segments.

This is a central detail of the method: the paper emphasizes repeated updates within a single training sample to approximate equilibrium behavior, whereas the current code treats training as a one-shot forward pass.

**Observed inconsistencies**

1. **Mismatch between training and evaluation**

   * Evaluation uses a loop (`while True: ... if all_finish: break`) to perform multiple forward passes until a stopping condition is met.
   * Training, by contrast, only does one forward call, without looping over segments.

2. **Mismatch between training and paper pseudocode**

   * Paper pseudocode clearly shows multiple forward passes per sample, with intermediate detach operations between segments.
   * Current training code ignores this, effectively discarding the deep supervision step.

3. **Carry persistence issue**

   * In `train_batch`, `train_state.carry` is initialized once and then reused across multiple batches.
   * This behavior may cause hidden states from one sample to leak into subsequent samples, which is not consistent with the intended segment-wise supervision described in the paper.
   * By contrast, evaluation reinitializes the carry for each batch, which is more faithful to the algorithm description.

### Comment by @shrivastava95 at 2025-08-20T07:05:33Z

It's true that only one forward pass per batch is computed during training (line 423 - 449 in [pretrain.py](https://github.com/sapientinc/HRM/tree/main/pretrain.py)). However, once a sequence is halted, the current batch is used to pick up the next sample (line 246 in [models/hrm/hrm_act_v1.py](https://github.com/sapientinc/HRM/tree/main/models/hrm/hrm_act_v1.py)), which is how the halted positions are refreshed with new training samples _only after_ a sample has been iterated over multiple segments until termination.
