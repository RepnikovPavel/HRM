H and L will cooperate to try their best to make answers exactly the same as the labels in the dataset if the original loss function is kept. I tried this on wikitext-2-v1, using the same evaluation metrics. I found that after just a few epochs of training, the model can achieve an accuracy of over 50% on the test set.

If I'm understanding the model and metrics correctly, it seems that HRM can efficiently learn to answer purely textual questions exactly as they appear in the dataset. I'm curious if there's an upper limit to this performance. Will the model only eventually overfits on these purely text-based tasks? I think this is worth more investigating.

Hello~ I didn't modify the model architecture to better fit NLP tasks, as I  thought that any structural changes might inadvertently degrade the performance. I simply reshaped the wikitext dataset to match the exact data format used in the Sudoku task in this project adapting the fixed 81-length input/output sequences accordingly. So, this is just aligning sequence dimension to the HRM time dimension instead of predicting in blocks. Thus, as I understand, the HRM could be overfitting all the time with this method to learn from wikitext but evaluation on the test set showed an unexpectedly good performance, which still puzzles me. Here is the code that I convert the wikitext to HRM Sudoku format: https://github.com/johnnyZeppelin/HRM-Idioma
