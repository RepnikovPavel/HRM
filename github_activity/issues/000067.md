### Comment by @dimitry12 at 2025-10-17T04:59:35Z

For ARC-AGI, each puzzle is a different "game". There is embedding layer containing a vocabulary mapping a puzzle ID to a latent, and this embedding layer has as many rows as there are puzzle variations (~1 million). Each row contains 512 float32 - for 2MB per entry.

```
>>> cp['_orig_mod.model.inner.puzzle_emb.weights'].shape
torch.Size([1045829, 512])
>>> cp['_orig_mod.model.inner.puzzle_emb.weights'].dtype
torch.float32
```

### Comment by @EruditionHerta at 2025-10-21T15:07:59Z

The size discrepancy occurs because PyTorch's state_dict() saves both parameters AND buffers, while the 27M figure refers only to learnable parameters.

The puzzle embedding uses a large lookup table that's stored as buffers rather than parameters. This is evident from the optimizer initialization which explicitly uses model.model.puzzle_emb.buffers(). These buffers are included in the state_dict() when saving checkpoints, significantly increasing the file size beyond just the 27M learnable parameters.

The 2GB checkpoint size is expected and correct: it contains the 27M model parameters PLUS the complete puzzle embedding lookup table and other necessary states for model restoration.
