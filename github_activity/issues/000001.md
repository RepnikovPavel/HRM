### Comment by @imoneoi at 2025-07-24T12:08:48Z

It appears there might be a misunderstanding regarding how ARC datasets and evaluation protocols function.

In ARC, each puzzle contains both 'train' examples (used to illustrate the rule) and 'test' examples (used to assess understanding). During evaluation, the model sees the few-shot 'train' examples provided explicitly for each puzzle and must infer the underlying rules to solve the associated 'test' examples.

Sometimes, we can run gradient descent on the few-shot 'train' examples during evaluation, called Test-Time Training (TTT), or  Test-Time Finetuning (TTFT). It's widely adopted by most high-ranking submissions, like [BARC](https://huggingface.co/barc0/potpourri-testtime-finetuning-100_test_aug100). Considering the ARC train and evaluation has very different difficulty levels, and HRM only use ~1000 examples without pretraining, it's pretty reasonable to also adopt TTT.

To clarify explicitly:

 - The examples labeled as 'train' within each evaluation puzzle are intentionally shown at test time to the model.

 - These 'train' examples within evaluation puzzles do not constitute data leakage since ARC's protocol inherently requires their use at test-time for puzzle-specific inference.

If there were genuine 100% data leakage - then model should have very close to 100% performance (perfect memorization). We also included a Transformer baseline. It should also perfectly memorize in a few steps if there were data leakage.

The existing evaluation methodology adheres strictly to the ARC competition guidelines, ensuring the validity of the reported results.
