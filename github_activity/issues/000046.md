### Comment by @kroggen at 2025-08-08T19:44:19Z

It works as the ACT (Adaptive Computation Time) control token, as can be seen here:

https://github.com/sapientinc/HRM/blob/4047578a02e5deba975c38a1f32392547e66c071/models/hrm/hrm_act_v1.py#L211

The halting decision for ACT is made based on position 0 (the puzzle embedding token). This token appear to serve 3 purposes:
* Global state aggregator, by collecting information from all grid positions
* Computation controller. It decides when to halt the reasoning process (with ACT)
* Attention sink: a stable/fixed position for attention offloading

But this is not mentioned on the paper (not sure they perceived it also works as attention sink)

And although there is code to not use this token, if we set the `puzzle_emb_ndim` to 0, the code fails with:

```
AttributeError: 'HierarchicalReasoningModel_ACTV1' object has no attribute 'puzzle_emb'
```

This token is set to `[0]` for Sudoku and Maze, but set to the puzzle id on ARC:

https://github.com/sapientinc/HRM/blob/4047578a02e5deba975c38a1f32392547e66c071/models/hrm/hrm_act_v1.py#L152

Not sure if fair, as the model will know what to do depending on the puzzle id. So it appears as not being generic (on the case of ARC) but biased/specialized on each task. The trained model may not work properly if we do not inform the task id later, and may fail on completely new/unseen tasks
