# RRN-27M: RRN, отмасштабированный в паритет с HRM

Проблема сравнения rrn/docs/comparison.md: RRN-96 имеет 191 114 параметров
против 27 275 266 у HRM — в 143 раза меньше, сравнение нечестное. Здесь
модель отмасштабирована до паритета по двум осям: число параметров и
inference FLOPs на пример. Модель — тот же `SudokuRRN` (пакет `rrn/`),
конфигурация: hidden_dim d=1168, num_steps T=13, embed_size 16,
edge_drop 0.4, оптимизатор и данные без изменений.

## Паритет параметров

Параметры RRN не зависят от T (веса шага общие). Точная формула при
embed_size e=16, из rrn/rrn/model.py:

- embeddings: (10+9+9)·e = 448
- input_layer: (48·d + d) + 3·(d² + d)
- msg_layer: (2d·d + d) + 3·(d² + d)
- lstm_ih + lstm_hh (без bias): 8d² + 4d² = 12d²
- output_layer: 10d + 10

Итого: 20d² + 66d + 458. При d=96: 184 778 + ... = 191 114 (сходится с
замеренным). Решение 20d² + 66d + 458 = 27 275 266 даёт d ≈ 1166.2;
ближайшая ширина, кратная 16 (ldmatrix/tensor-core выравнивание):
d=1168 → **27 362 026 параметров (+0.32% к HRM)**.

## Паритет inference FLOPs

HRM test fwd (16 ACT-сегментов; ранняя остановка на этом датасете не
срабатывает — замеренное 6857 µs/elem / 428 µs за сегмент = 16.0):
16 сегментов × 24 layer-pass × 82 токена (81 + 1 puzzle-токен,
hrm_act_v1.py:130) × 6 822 402 FLOP/токен/слой (torch.profiler
with_flops на одном блоке, hrm-train:cuda12) = **214.9 GFLOP/пример**.

RRN test fwd на пример (d=1168), matmul-FLOPs (проверено torch.profiler
with_flops: 147.9 GFLOP при T=9 → 16.36 GFLOP/шаг, ровно формула ниже):
- input_layer: 81·2·(48·1168 + 3·1168²) = 0.67 GFLOP
- шаг: первый слой сообщений факторизован по линейности
  (W1·[h_i;h_j] = W1a·h_i + W1b·h_j) — GEMM по 81 узлу, а не по 1620
  рёбрам: hw12 81·2·2d² = 0.44G; слои 2-4 сообщений по рёбрам
  1620·2·3d² = 13.27G; LSTM 81·2·12d² = 2.65G → 16.36 GFLOP/шаг
- T=13 шагов + голова последнего шага → **213.4 GFLOP/пример (−0.7% к HRM)**

T=9 давал бы 147.9 GFLOP (−31%), T=14 — 229.8 (+6.9%); T=13 — почти
точный паритет. Ширина вместо глубины — стандартный способ
масштабирования RRN; шагов меньше, чем у эталона (32), т.к. каждый шаг
стал в 149 раз шире.

## Обучение

те же train/test файлы. rrnfast к d=1168 не применим (ядро зашито на
d=96), используется эталонный `_step` с activation checkpointing;
